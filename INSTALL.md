# Hermes Agent — Docker Install (slim git-pip variant)

Slimmer Docker image (~1.6 GB vs ~7.4 GB upstream — 5× smaller) for Hermes. Clones the upstream source, builds the web dashboard + TUI front-end, installs Python deps via `pip install -e` with hand-picked extras, then purges the build-time toolchain (keeps Node.js as the TUI's runtime). Faster to build (~3 min vs ~15 min), smaller to ship, sufficient for chat + dashboard + TUI + MCP + messaging bridges + Google APIs + voice/STT + Honcho memory. Trades Playwright/browser tools for image size.

## Quick start

```bash
# 1. Clone this branch
git clone --branch feat/hermes-install-slim --single-branch --depth 1 \
    https://github.com/katysei/hermes-agent.git hermes-agent-slim
cd hermes-agent-slim

# 2. Run the orchestrator
./install-docker.sh

# 3. Add your model provider key (see below)

# 4. Use it
open http://localhost:9119                # dashboard
KEY=$(grep ^API_SERVER_KEY= .env | cut -d= -f2)
curl http://localhost:8642/v1/chat/completions \
    -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
    -d '{"model":"hermes-agent","messages":[{"role":"user","content":"hi"}]}'
```

Or one-liner from anywhere:

```bash
curl -fsSL https://raw.githubusercontent.com/katysei/hermes-agent/feat/hermes-install-slim/install-docker.sh | bash
```

## What's in the image (single-branch view)

```
1 monolithic image @ ~1.6 GB containing:
  Python:     full agent loop, gateway, cron, all tools
  HTTP:       OpenAI-compatible API on :8642 (Bearer auth)
  Dashboard:  SPA on :9119 (React, served by Python)
  TUI:        React+Ink CLI accessible via `hermes --tui` inside the container
  MCP:        server (stdio always; streamable HTTP via HERMES_MCP_HTTP_PORT)
  Skills:     25+ bundled categories from upstream sparse-clone
  Memory:     built-in (MEMORY.md/USER.md) + Honcho SDK ready to enable
  Bridges:    Telegram + Discord + Slack SDKs (configure with tokens)
  Google:     Gmail / Drive / Calendar / Sheets / Docs APIs
  Voice:      faster-whisper for local STT
  ACP:        Agent-Client Protocol adapter
```

What's **NOT** in this image (would need to be added — see "Installing missing parts" below):

- Browser tools (Playwright/Chromium) — ~600 MB
- Matrix / Modal / Daytona / Vercel / AWS Bedrock provider SDKs
- Alternative external-memory providers (mem0, openviking, hindsight, …)
- DingTalk / Feishu / TTS-premium / HomeAssistant / SMS extras

## Two `.env` files — what goes where

### `<install-dir>/.env` — compose runtime config

Lives next to `docker-compose.yml`. Auto-loaded by `docker compose`. **Auto-generated by `install-docker.sh`.**

| Variable | Required? | Set by | What it does |
|---|---|---|---|
| `API_SERVER_KEY` | yes | install script | Bearer token for the HTTP API on `:8642`. Without it the API server refuses to start. |
| `HERMES_UID` | recommended | `id -u` at invocation | Maps the container's `hermes` user to your host UID so bind-mount file ownership stays consistent. |
| `HERMES_GID` | recommended | `id -g` at invocation | Same for primary group. |

### `~/.hermes/.env` — runtime provider keys

Lives inside the bind-mount target (`~/.hermes/` on host, `/opt/data/` inside container). Read by Hermes for provider credentials. **You must populate at least one provider key.**

At least one of:

| Variable | Provider | Get from |
|---|---|---|
| `ANTHROPIC_API_KEY` | Anthropic (Claude / Opus / Sonnet / Haiku) | https://console.anthropic.com/keys |
| `OPENAI_API_KEY` | OpenAI (GPT-5 / GPT-4o / …) | https://platform.openai.com/api-keys |
| `OPENROUTER_API_KEY` | OpenRouter | https://openrouter.ai/keys |
| `GEMINI_API_KEY` | Google Gemini | https://aistudio.google.com/apikey |
| `GROQ_API_KEY` | Groq | https://console.groq.com/keys |
| `DEEPSEEK_API_KEY` | DeepSeek | https://platform.deepseek.com/api_keys |
| `XAI_API_KEY` | xAI (Grok) | https://console.x.ai/ |
| `MISTRAL_API_KEY` | Mistral | https://console.mistral.ai/api-keys |

Then `~/.hermes/config.yaml`:

```yaml
model:
  default: claude-opus-4-7    # or whichever model the provider supports
  provider: anthropic         # or openai, openrouter, gemini, ...
```

## Installing missing parts

The image bakes in `[mcp,web,messaging,google,acp,voice,honcho]` plus the TUI front-end (built from ui-tui/). Still missing: **browser tools (Playwright/Chromium)** and the long tail of less-used extras (matrix, bedrock, modal, daytona, vercel, dingtalk, feishu, tts-premium, other external-memory providers like mem0/openviking/hindsight/etc). Three ways to add what you need.

### Option 1 — bake into the image (clean, permanent)

Edit `Dockerfile` and add extras to the `pip install` line:

```dockerfile
# default
RUN pip install --no-cache-dir 'hermes-agent[mcp,web]' aiohttp

# with messaging bridges (Telegram, Discord, Slack)
RUN pip install --no-cache-dir 'hermes-agent[mcp,web,messaging]' aiohttp

# with voice / STT
RUN pip install --no-cache-dir 'hermes-agent[mcp,web,voice]' aiohttp

# everything (closer to upstream full build, but still no Playwright/TUI)
RUN pip install --no-cache-dir 'hermes-agent[mcp,web,messaging,voice,acp,google,bedrock,dingtalk,feishu]' aiohttp
```

Then rebuild:

```bash
HERMES_UID=$(id -u) HERMES_GID=$(id -g) docker compose up --build -d
```

Each extra you add bumps the image size. `[messaging]` is ~50 MB. `[voice]` is ~400 MB (faster-whisper + ctranslate2). Browser tools (Playwright + Chromium) are ~600 MB and need extra apt-get work — at that point you're rebuilding the full upstream Dockerfile, so just use the `feat/hermes-install` branch instead.

### Option 2 — install into the running container (quick + dirty)

For a one-off test without rebuilding:

```bash
docker exec hermes pip install 'hermes-agent[messaging]'
docker compose restart gateway
```

The packages land inside the running container's filesystem. **They're lost when the container is recreated** (e.g., on `docker compose down` + `up -d`). Fine for "let me try this for an hour" — bad for "I want this permanently."

### Option 3 — switch to the full-build branch

If you find yourself wanting most of the missing parts (especially browser tools or the TUI), the pip approach is fighting you. Switch to `feat/hermes-install` — same authoring style, but the full upstream build. ~10 min one-time cost, ~7.4 GB image, everything works out of the box.

```bash
cd ..
git clone --branch feat/hermes-install --single-branch --depth 1 \
    https://github.com/katysei/hermes-agent.git hermes-agent-full
cd hermes-agent-full
./install-docker.sh    # builds full image
```

### What about Playwright/Chromium (browser tools)?

Playwright needs both the Python package **and** Chromium installed via `playwright install --with-deps chromium`. The Chromium install is ~500 MB and pulls in a bunch of X11/font deps via apt. Adding it to this slim Dockerfile is doable but at that point you're 80% of the way to upstream's full build — so just use the full-build branch.

If you really want it here only: add to the Dockerfile:

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends nodejs npm
RUN pip install --no-cache-dir 'hermes-agent[mcp,web]' aiohttp playwright
RUN playwright install --with-deps chromium
```

### What about the TUI?

The TUI's React+Ink front-end isn't on PyPI at all — it's only in the upstream repo's `ui-tui/` source tree. You can't `pip install` it. To use the TUI, either:

- Switch to the full-build branch (which builds `ui-tui/` from source), or
- Run `hermes --tui` on your **host** machine (bypassing Docker entirely — install Hermes on the host with `pip install hermes-agent && npm i -g ...`, point at the container's gateway via `HERMES_GATEWAY_URL`).

## Optional — enable MCP over streamable HTTP

If you want the SDK's `Hermes.via_mcp("http://localhost:8000/mcp")` transport:

1. Edit `docker-compose.yml`:
   ```yaml
   ports:
     - "127.0.0.1:8642:8642"
     - "127.0.0.1:8000:8000"   # add this
   environment:
     - HERMES_MCP_HTTP_PORT=8000   # uncomment
   ```
2. `docker compose up -d --force-recreate`
3. The MCP-HTTP side-process starts inside the container, reachable at `http://localhost:8000/mcp`.

## Lifecycle

```bash
docker compose ps                                   # what's running
docker compose logs -f gateway                      # tail logs
docker compose stop                                 # pause
docker compose down                                 # remove containers (image + ~/.hermes survive)
HERMES_UID=$(id -u) HERMES_GID=$(id -g) docker compose up -d   # restart

docker compose down --rmi local                     # also drop the image
./install-docker.sh                                 # full re-install from scratch
```

Your `~/.hermes/` is never touched by these — config, secrets, sessions, memories all survive.

## What's NOT auto-configured

- Your provider API keys — add to `~/.hermes/.env` yourself
- Your `~/.hermes/config.yaml` model selection — defaults to upstream's choice
- Your `SOUL.md` persona — optional, write your own at `~/.hermes/SOUL.md` if wanted
